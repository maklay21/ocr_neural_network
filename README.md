# Постобработка OCR-паспортов

`postprocess.py` оценивает распознанные поля паспорта и принимает документ, только если модель и дополнительные проверки не нашли оснований для отказа. Скрипт не обрабатывает изображения и не выполняет OCR.

# Обучение нейросети

Для оценки OCR используется нейросеть OCRClassifier. Она получает 99 числовых признаков, извлечённых из распознанных данных и метаданных снимка, и выдаёт 10 оценок — по одной для каждого поля паспорта. У сети три обучаемых слоя Linear: два скрытых слоя с ReLU и Dropout и выходной слой.

При обучении нейросеть предсказывает правильность каждого из 10 полей. Дополнительно скрипт сопоставляет символы OCR с `train_labels.jsonl` и обучает калибратор вероятности ошибки символа по его `char_conf`. Вероятности символов объединяются в оценку риска ошибки документа. На calibration совместно подбираются пороги оценки документа и символьного риска; целевая точность на calibration — 100% (ноль ошибочно принятых документов на этой части данных).

В последнем запуске на holdout из 600 документов принято 75, из них 4 содержали ошибки. Их можно посмотреть в `solution/holdout_false_accepts.jsonl`. Ошибки с высокой уверенностью OCR показывают ограничение метода: калибратор не может надёжно предсказать ошибку, если похожие примеры редко встречались в обучающей выборке, также некоторые словарные ошибки выдавали высокую уверенность OCR.

## Запуск на test

Команду нужно запускать из корня проекта:

```bash
python3 solution/postprocess.py data/test_predictions.jsonl solution/answers.jsonl
```

Аргументы — входной JSONL с результатами OCR и путь выходного файла. Скрипт загружает готовую модель из `solution/calibrator.json`, применяет справочник `reference/subdivisions.csv` и записывает по одной строке на документ. Для `accept` добавляются все 10 распознанных полей; у `reject` поля отсутствуют. В конце печатается число принятых и отклонённых документов.

Обычная обработка не требует PyTorch или доступа к интернету. Готовая нейросеть выполняется средствами стандартной библиотеки Python. Для запуска необходимы файлы модели и справочник подразделений.

## Обучение

Из корня проекта выполните:

```bash
python3 solution/postprocess.py --train
```

Для обучения установите PyTorch CPU:

```bash
python3 -m pip install torch --index-url https://download.pytorch.org/whl/cpu
```

Обучение использует пары `data/train_predictions.jsonl` и `data/train_labels.jsonl`. Данные с фиксированным seed делятся на fit (60%), calibration (20%) и holdout validation (20%). Нейросеть предсказывает правильность каждого OCR-поля, а калибратор символьного риска обучается на выравнивании OCR-текста с `train_labels` на fit. На calibration совместно выбираются пороги оценки документа и риска символов при целевой точности 100% на этой выборке. Holdout используется для отдельной оценки; цель калибровки не гарантирует ноль ошибок на новых данных.

При `--train` скрипт обучает сеть и калибратор символьного риска, сохраняет общую модель в `solution/calibrator.json`, формирует ответы для `data/test_predictions.jsonl` в `solution/answers.jsonl` и записывает диагностические JSONL-файлы. Если нужно повторно откалибровать риск символов на сохранённых весах без обучения сети, используйте `python3 solution/postprocess.py --calibrate-risk`.

- `solution/rejected_records.jsonl` — отклонения holdout и test с причинами; при обычном запуске на test файл содержит только отказы test;
- `solution/holdout_false_accepts.jsonl` — принятые на holdout документы, у которых хотя бы одно поле отличается от разметки.

## Логика принятия

Помимо покомпонентной оценки модели проверяются наличие и формат полей, допустимый порядок дат и правила валидности паспорта, сверка даты рождения и пола с MRZ, а также соответствие названия подразделения распознанному коду в справочнике. Эти проверки дополняют оценку OCR и могут отклонить запись независимо от оценки нейросети.

`evaluate.py` сравнивает ответы и разметку только для соответствующих документов; он считает точность полей, но не проверяет действительность паспорта. Нельзя сравнивать test-ответы с train-разметкой. Для test-разметки в проекте меток нет, поэтому фактическое число ошибок среди принятых test-документов неизвестно.
